# Development

The distribution is `Net-Quiche`; the main public module is `Net::Quiche`.
`Net::Quiche::XS` is the native layer. The proposed GitHub repository is
`Code-Hex/p5-Net-Quiche`.

## Native dependency

Install Perl development headers, a C compiler, make, Git, pkg-config, Rust
1.88 or later, and CMake. On macOS, install Xcode Command Line Tools first.
The Perl and quiche builds must target the same architecture.

The helper uses quiche 0.29.3 at commit
`55886df3be579579207104c8e645825b6347a209`, with the tested Rust dependency
resolution in `builder/quiche-Cargo.lock`. Run from the repository root:

```sh
sh tools/build-quiche.sh
export PKG_CONFIG_PATH="$PWD/.deps/quiche/target/release${PKG_CONFIG_PATH:+:$PKG_CONFIG_PATH}"
pkg-config --modversion quiche
```

The script checks an existing checkout and lockfile before building. It does
not replace a different checkout or lockfile. Rust crates and BoringSSL build
artifacts stay under `.deps/` or Cargo's cache. They are not distributed.

On macOS the build sets `CARGO_C_LIBDIR=@rpath`. A previously built quiche
with a different install name needs a rebuild; Cargo does not track changes
to that variable. The helper adds the versioned shared-library symlink on
macOS and Linux. Keep the library at that path while using the Perl module;
moving it requires relinking the XS module.

An existing system quiche installation also works if it provides its C API
and `pkg-config` reports a released version of at least 0.29.3. This is a
minimum version check, not a claim that every later C ABI has been tested.
For custom or static linking, supply both flags explicitly:

```sh
QUICHE_CFLAGS='-I/path/to/quiche/include' \
QUICHE_LIBS='-L/path/to/quiche/lib -Wl,-rpath,/path/to/quiche/lib -lquiche' \
perl Build.PL
```

For static linking, include Rust/BoringSSL's system libraries in
`QUICHE_LIBS`. `PKG_CONFIG` can select a different pkg-config executable.
The module also checks the actual quiche version at load time.

## Perl dependencies and tests

Use a Perl with cpanminus available. A local dependency prefix is optional:

```sh
cpanm --local-lib-contained local --installdeps --with-develop --with-recommends .
export PATH="$PWD/local/bin:$PATH"
export PERL5LIB="$PWD/local/lib/perl5${PERL5LIB:+:$PERL5LIB}"
perl Build.PL
./Build
./Build test
perl -Mblib -MNet::Quiche -E 'say Net::Quiche::version()'
```

For an installed distribution, `cpanm --installdeps .` is enough. Minilla and
the develop dependencies are only needed by maintainers. The optional
`PAGI::App::WrapPSGI` dependency enables the PSGI example and tests. Without
it, `t/psgi-http3.t` reports a skip. Request bodies are buffered by this adapter.

The public quiche test certificate and key are included under `t/fixtures`
with their original license. Native handshake and HTTP/3 tests therefore
run without a quiche source checkout. These credentials are only for tests.

`t/curl-http3.t` requires a curl built with the `HTTP3` feature. It searches
PATH by default. To select the Homebrew build on an Apple Silicon Mac:

```sh
export NET_QUICHE_CURL=/opt/homebrew/opt/curl/bin/curl
"$NET_QUICHE_CURL" --version
./Build test
NET_QUICHE_TEST_HOST=::1 ./Build test --test_files t/curl-http3.t
```

The curl test makes real GET and POST requests through the UDP listener.
The in-memory quiche tests exercise response backpressure and POST streaming
with controlled flow limits. IPv6 tests skip when the host has no IPv6
loopback. Read the skip messages; a skipped interoperability test is not a pass.

For manual frame and stream debugging, build Cloudflare's h3i:

```sh
cargo build --manifest-path .deps/quiche/Cargo.toml --locked --release -p h3i
perl -Mblib tools/check-http3-env.pl
```

`NET_QUICHE_H3I` selects another h3i executable. The checker expects the
pinned quiche checkout and verifies curl, h3i and the bundled TLS fixtures.

## Minilla workflow

Minilla 3.3.2 generates `Build.PL`, `META.json` and `README.md`. Edit
`cpanfile` for dependencies, `minil.toml` for distribution metadata,
`builder/MyBuilder.pm` for native compiler/linker discovery, and
`lib/Net/Quiche.pm` for the README text. The XS source is
`lib/Net/Quiche/XS.xs`. Preserve the package name `Net::Quiche::XS` so
`XSLoader` finds the right shared object.

```sh
git add cpanfile minil.toml builder lib t examples tools doc Changes
minil test
minil dist
```

Minilla gathers Git-tracked files, including files staged before the first
commit. Stage new source and fixtures before testing the distribution.
`minil test` and `minil dist` build and test in an isolated source tree.
`minil dist` creates `Net-Quiche-0.013.tar.gz` without uploading anything.
`MANIFEST` and `META.yml` in the archive are generated by Minilla. The Perl 5
license text is tracked in `LICENSE`.

Keep generated `Build.PL`, `META.json` and `README.md` in Git so a fresh clone
can install without Minilla. After editing POD, metadata or dependencies,
regenerate them without bumping the version:

```sh
perl -MMinilla::Project -e 'Minilla::Project->new->regenerate_files'
git add Build.PL META.json README.md
```

`Changes` deliberately contains only the first public release notes. The
earlier local version increments were not CPAN releases. Version 0.013 is
preserved. `minil release` uploads to CPAN and pushes commits/tags; run it
only when making an actual release, after reviewing the archive and PAUSE
indexing permissions for the `Net::Quiche::*` and `PAGI::*` modules.

## GitHub

The intended repository name is `p5-Net-Quiche`, matching the CPAN distribution
and leaving room for the client and server modules. The workflows test
Ubuntu and macOS and build the source archive on Ubuntu. Their first remote
run is still needed to establish those runner results.

After reviewing the local files, create and publish the repository:

```sh
gh repo create Code-Hex/p5-Net-Quiche --public --source=. \
  --description 'Perl bindings for quiche, with an HTTP/3 client and PAGI server' \
  --remote=origin
git push -u origin main
```

## PAGI contract and remaining work

The conformance subset targets PAGI 0.002008, specification 0.5, and the
PAGI-Server 0.002012 compliance document. It is not a full PAGI conformance
claim. To inspect the same upstream references:

```sh
git clone --depth 1 --branch v0.002008 \
  https://github.com/jjn1056/pagi.git .build-deps/pagi-spec-0.002008
git clone --depth 1 --branch v0.002012 \
  https://github.com/jjn1056/pagi-server.git .build-deps/pagi-server-0.002012
perl tools/check-pagi-conformance-env.pl
```

Lifespan, WebSocket, TLS introspection, request/response trailers and file/fh
response events are not implemented. Retry/token handling, migration and
production resource limits also remain. Shutdown has a bounded grace period
and an H3_NO_ERROR close; completion of a send Future means quiche accepted
the bytes, not that the peer acknowledged them.

Upstream build and authoring references:

- https://github.com/tokuhirom/Minilla/tree/v3.3.2
- https://curl.se/docs/http3.html
